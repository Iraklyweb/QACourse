Лекция «Куки: что это такое и зачем они нужны»

 

Куки (cookies) — это небольшие фрагменты данных, которые сервер отправляет клиенту (обычно браузеру), и которые сохраняются на стороне клиента для последующего использования. Они позволяют серверу «запоминать» пользователя и его действия между сессиями. Куки часто используются для авторизации, персонализации контента и отслеживания действий пользователя.

 

Как работают куки

Сервер создаёт куки: Когда клиент делает запрос (например, авторизуется), сервер отправляет заголовок Set-Cookie с данными, которые нужно сохранить. Пример: Set-Cookie: session_id=abc123; Max-Age=3600; HttpOnly; Secure

Клиент сохраняет куки: Браузер или другое клиентское приложение сохраняет эти данные локально.

Клиент отправляет куки на сервер: При каждом последующем запросе браузер автоматически добавляет заголовок Cookie, отправляя сохранённые данные серверу.

Пример: Cookie: session_id=abc123

 

Основные параметры куки

  1. Name=Value: Основная пара, которая содержит название и значение куки. Пример: session_id=abc123.

  2. Max-Age/Expires: Указывает срок действия куки. Если срок истёк, куки удаляется.

  3. HttpOnly: Куки доступны только для HTTP-запросов, их нельзя прочитать или изменить через JavaScript.

  4. Secure: Куки передаются только по HTTPS.

 

Типы куки

Существует несколько типов куки, которые различаются по времени хранения, источнику создания и назначению. В зависимости от задачи они могут использоваться по-разному, но стандартная классификация включает:

  • Сессионные куки Хранятся только в течение текущей сессии браузера и удаляются после его закрытия. 📌 Пример: сохранение состояния авторизации, чтобы пользователь не вводил пароль при каждом переходе по страницам.

  • Постоянные куки Хранятся на устройстве до истечения срока действия (Max-Age или Expires) или пока их не удалит пользователь вручную. 📌 Пример: сохранение настроек языка на сайте или данных для автоматического входа.

  • Зомби-куки (Evercookies) Эти куки восстанавливаются даже после удаления стандартными методами, так как данные о них могут храниться в нескольких местах (Local Storage, IndexedDB, Flash-хранилище и других). Они используются для слежки и отслеживания пользователей даже после очистки браузера. 📌 Пример: повторное появление рекламы, несмотря на удаление куки, или сохранение настроек на сайте, даже если пользователь очистил браузер.

 

Куки и безопасность

Куки часто используются для хранения токенов авторизации или другой важной информации, поэтому их настройка должна быть безопасной:

  • Используйте HttpOnly для защиты данных от доступа через JavaScript.

  • Всегда добавляйте Secure, чтобы куки передавались только по HTTPS.

 

Пример работы с куки

Сценарий авторизации:

  1. Клиент отправляет данные для входа: POST /login HTTP/1.1

Host: example.com

Content-Type: application/json

{

  "username": "user",

  "password": "pass"

}

  1. Сервер возвращает ответ с куки: 200 OK

Set-Cookie: session_id=abc123; Max-Age=3600; HttpOnly; Secure

  1. Клиент отправляет последующие запросы с куки: GET /profile HTTP/1.1

Host: example.com

Cookie: session_id=abc123

  1. Сервер проверяет куки и возвращает данные профиля.

 

Что важно помнить

  • Куки клиентские: Хранятся и отправляются браузером. Проверяйте их через вкладку Application в DevTools.

  • Куки серверные: Создаются и отправляются сервером. Проверяйте их в заголовках Set-Cookie.

 

Итог

В большинстве случаев вы будете работать с куки так же, как и с клиентским кэшем — ваша основная задача будет заключаться в их очистке. Проверять куки придётся редко, только по прямому запросу или в рамках специфических требований. Без чётких указаний или необходимости влезать в куки нет смысла.

Однако, если работа с куки всё же потребуется, основные задачи будут такими:

  1. Очистка куки: Убедитесь, что данные авторизации или персонализации очищены, чтобы проверить сценарии с "чистым" состоянием.

  2. Проверка заголовков Set-Cookie: Убедитесь, что сервер правильно устанавливает куки и их параметры.

  3. Модификация и удаление: Проверьте, как система реагирует на изменение или отсутствие куки.

Такой подход обеспечит вам уверенность в работе с куки и позволит избежать лишних действий.
