Лекция «Метод POST: как работает и зачем нужен»

 

Метод POST используется для отправки данных на сервер. В отличие от GET, который только запрашивает данные, POST передаёт информацию, создаёт новые ресурсы или запускает серверные процессы.

Если сравнивать с реальной жизнью, POST — это как заполнение анкеты в банк: вы передаёте свои данные, а система их принимает, обрабатывает и создаёт новый профиль клиента.

 

Как работает POST?

Метод POST позволяет клиенту передавать данные на сервер, создавая новый ресурс или выполняя действие. POST может создавать несколько ресурсов или выполнять нестандартные операции. Например:

  1. Исходный список пользователей в базе:

[

  {

    "id": 1,

    "name": "Alice",

    "email": "alice@example.com"

  }

]

  1. Клиент отправляет POST-запрос с данными нового пользователя:

POST /users HTTP/1.1  

Host: api.example.com  

Content-Type: application/json  

{

  "name": "Bob",

  "email": "bob@example.com"

}

→ Здесь передаётся информация о новом пользователе.

  1. Сервер обрабатывает запрос:

    • Проверяет, корректны ли передаваемые данные.

    • Создаёт новый ресурс (например, запись в базе данных).

    • Генерирует новый id для созданного пользователя.

    • Записывает данные в базу.

  2. Обновлённый список пользователей после POST:

[

  {

    "id": 1,

    "name": "Alice",

    "email": "alice@example.com"

  },

  {

    "id": 2,

    "name": "Bob",

    "email": "bob@example.com"

  }

]

→ Новый пользователь Bob добавился в список.

  1. Сервер отправляет ответ:

    • 201 Created, если ресурс успешно создан.

    • 200 OK, если ресурс успешно создан или если запрос обработан успешно, но новый ресурс не создаётся (например, при поиске через POST или обработке формы).

    • 400 Bad Request, если данные некорректны.

    • 404 Not Found, если путь указан неверно.

 

Возможный пример ответа:

HTTP/1.1 201 Created  

Location: /users/2  

Content-Type: application/json  

{

  "id": 2,

  "name": "Bob",

  "email": "bob@example.com"

}

Метод POST удобен, когда нужно создать новый ресурс (например, пользователя, заказ, комментарий) или запустить серверный процесс, который требует передачи данных (например, авторизация, обработка форм, загрузка файлов).

 

POST как альтернатива GET

POST может использоваться вместо GET в тех случаях, когда:

  • Данные не помещаются в URL (например, сложные фильтры, массивы параметров).

  • Запрос содержит вложенные структуры (например, JSON с несколькими уровнями вложенности).

  • Конфиденциальные данные не должны отображаться в URL (например, при поиске по персональным данным).

Пример использования POST для поиска:

POST /search HTTP/1.1  

Host: api.example.com  

Content-Type: application/json  

{

  "query": "смартфон",

  "filters": { 

    "brand": "Apple", 

    "price": { "min": 1000, "max": 5000 } 

  }

}

Здесь передаются сложные фильтры, которые в GET-запросе превратились бы в перегруженный URL. POST позволяет передавать такие данные в теле запроса, делая его удобнее и безопаснее.

 

Основные свойства метода POST

POST не является идемпотентным

  • Повторный вызов одного и того же POST-запроса может привести к разным результатам.

  • Например, два одинаковых запроса на создание пользователя могут создать двух разных пользователей с разными id.

  • В отличие от PUT, который заменяет существующий ресурс, POST создаёт новые записи или выполняет серверные процесс.

Влияние на безопасность и состояние сервера

  • POST изменяет состояние сервера, так как передаёт данные, которые могут создавать, изменять или запускать серверные процессы. Тем самым POST небезопасен с точки зрения изменения данных на сервере.

  • Безопасен с точки зрения передачи данных, так как они передаются в теле запроса, а тело в свою очередь шифруется.

  • Без HTTPS данные остаются незащищёнными и могут быть перехвачены.

  • В отличие от GET, POST скрывает данные от истории браузера и логов URL, но передаваемая информация остаётся уязвимой, если не используется шифрование на уровне соединения (TLS/HTTPS).

  • Как и другие методы изменения данных, POST требует авторизации, если ресурс защищён.

Передача данных

  • POST передаёт только переданные данные, не затрагивая остальные ресурсы.

  • Это делает запросы компактнее и быстрее, особенно при передаче больших объёмов информации.

Ограничение длины URL отсутствует

  • Данные передаются в теле запроса, а не через URL, поэтому POST не ограничен по размеру данных.

  • Однако некоторые API могут накладывать свои лимиты на размер тела запроса.

Форматы данных

  • Чаще всего используется JSON, так как REST API обычно работают с этим форматом.

  • Однако POST может поддерживать XML, файлы или другие форматы в зависимости от API.

Кэширование

  • POST не кешируется браузерами и прокси-серверами, так как он изменяет данные.

  • Однако сервер может использовать заголовки ETag и Last-Modified, чтобы проверять актуальность данных перед выполнением запроса.

 

Дополнительные особенности метода POST

POST отправляет данные в теле запроса

  • В отличие от GET, который передаёт параметры в URL, POST использует тело запроса.

  • Это делает его удобным для структурированных данных (JSON, XML) и больших объёмов информации.

POST требует существования обработчика

  • Если сервер не поддерживает обработку POST-запросов по указанному пути, он вернёт 404 Not Found.

  • Если данные в POST-запросе некорректны, сервер вернёт 400 Bad Request.

POST может содержать query-параметры в URL

Хотя POST передаёт основные данные в теле запроса, query-параметры в URL также могут использоваться.

Это может быть полезно для передачи метаинформации, например: POST /users?admin=true HTTP/1.1  

Host: api.example.com  

Content-Type: application/json  

{

  "name": "Bob",

  "email": "bob@example.com"

}

В этом примере тело запроса создаёт пользователя, а query-параметр admin=true указывает, что он должен быть администратором.

POST требует существования ресурса

  • Если объект существует, POST может взаимодействовать с ним, отправляя данные.

  • Если ресурс не найден, сервер вернёт 404 Not Found, так как POST не создаёт ресурс автоматически, если API этого не предусматривает.

POST выполняется на уровне коллекции ресурсов

POST-запрос обычно выполняется для коллекций, например: POST /users

POST — универсальный метод, который подходит для передачи данных, создания новых ресурсов и выполнения серверных процессов.

 

Итог

Метод POST используется для отправки данных на сервер и создания новых ресурсов. Он позволяет передавать сложные структуры данных, такие как JSON, файлы и формы, без ограничений на длину URL. POST удобен для случаев, когда необходимо выполнить серверную операцию или передать конфиденциальные данные.

 

Как тестируют POST?

  • Если есть доступ к БД, проверяют, создался ли новый ресурс и соответствует ли он переданным данным.

  • Если доступа к БД нет, делают GET-запрос, чтобы убедиться, что данные появились.

  • Проверяют, возвращает ли сервер корректные статус-коды (200 OK,201 Created, 400 Bad Request при ошибке).

  • Тестируют обработку некорректных данных (например, отправку пустых значений).

  • Проверяют, выполняет ли сервер ожидаемые действия, например, не создаёт ли он дублирующиеся записи.

POST применяется, когда требуется передача данных на сервер, создание ресурса или выполнение серверного процесса.
