Лекция «Фронтенд и бэкенд: что это и в чём разница?»

 

В веб-разработке и тестировании часто используются термины фронтенд и бэкенд (сокращённо фронт и бэк). Они обозначают разные части системы, но тесно связаны между собой. Фронтенд иногда называют клиентской частью, потому что он работает на стороне пользователя — в браузере, мобильном приложении или другом интерфейсе. Бэкенд называют серверной частью, так как он выполняет основную логику, обрабатывает данные и управляет их хранением.

Фронтенд без бэкенда может существовать, если это просто статическая страница, но как только появляется необходимость в авторизации, обработке данных или взаимодействии с базой, без бэкенда уже не обойтись.

 

Фронтенд (Frontend)

Фронтенд — это та часть приложения, которая отвечает за отображение интерфейса и взаимодействие пользователя с системой.

Фронтенд включает в себя несколько ключевых элементов:

  • Вёрстка (HTML, CSS) — основа отображения страницы.  HTML (HyperText Markup Language) — это язык разметки, который определяет структуру веб-страницы. Он описывает, какие элементы будут на странице: заголовки, текст, кнопки, формы, изображения. CSS (Cascading Style Sheets) — это каскадные таблицы стилей, которые управляют внешним видом HTML-элементов: цветами, шрифтами, размерами, расположением. Без CSS сайт выглядел бы просто как набор текста и кнопок без стилизации.

  • Логика на стороне клиента (JavaScript, React, Vue, Angular) — отвечает за интерактивность.

    • Анимации, выпадающие меню, динамическое изменение контента — всё это делает JavaScript.

    • Фреймворки, такие как React или Vue, позволяют строить сложные веб-приложения, которые работают без перезагрузки страниц.

  • Фреймворки и библиотеки. Фреймворк — это готовый каркас для разработки. Он задает структуру проекта и определяет, как строить приложение. Например, Angular — это фреймворк, потому что он включает в себя всё: работу с интерфейсом, маршрутизацию страниц и логику приложения. Библиотека — это набор инструментов, который можно использовать в проекте без строгих правил. Например, React — это библиотека, потому что она отвечает только за отображение интерфейса, а остальное (маршрутизация, управление состоянием) выбирает сам разработчик. Разница:

    1. Фреймворк диктует, как строить приложение.

    2. Библиотека даёт инструменты, но не заставляет следовать определенной структуре.

    Во фреймворке код подстраивается под его принципы, а в библиотеке разработчик сам решает, как её использовать.

  • Запросы к серверу (API, AJAX, Fetch, WebSockets) — механизм взаимодействия с бэкэндом.

    API — клиент отправляет запросы на сервер и получает ответы (например, в формате JSON).

    AJAX — позволяет делать запросы без перезагрузки страницы, обновляя только нужные данные.

    Fetch — современный метод для асинхронных запросов для обработки ответов.

    WebSockets — обеспечивает постоянное соединение с сервером для обмена данными в реальном времени. 

Без этих компонентов веб-приложение либо вообще не будет функционировать, либо превратится в обычную статичную страницу.

 

Бэкенд (Backend)

Бэкенд — это внутренняя часть системы, которая выполняет обработку данных и логику работы приложения.

Бэкенд обычно включает:

  • Сервер — принимает запросы от клиента и отправляет ответы.

  • Бизнес-логику — обрабатывает данные, выполняет расчёты, проверяет права доступа.

  • Базу данных — хранит информацию (пользователи, заказы, сообщения).

Когда пользователь логинится, фронтенд отправляет данные на сервер, а бэкенд проверяет их, создаёт сессию и отправляет ответ. Если данные неверны, сервер вернёт ошибку.

 

Итог

В работе вы можете тестировать только бэкенд, если у системы нет клиентского интерфейса или тестируются API и серверная логика отдельно. Но когда есть фронтенд, тестировать приходится и его, и бэкенд одновременно, особенно если часть логики выполняется на сервере.

Что интереснее тестировать — вопрос индивидуальный. В каждой части есть свои инструменты, подходы и особенности. Не зацикливайтесь на том, что хотите работать только с чем-то одним. Важно уметь тестировать и фронт, и бэк, а навык приходит со временем. Главное — понимать, как они взаимодействуют.
