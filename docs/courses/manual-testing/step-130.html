Лекция «Серверные проблемы: База данных и 500 ошибки»

 

1. Сервер не отвечает (500 Internal Server Error)

Проблема: Сервер не может обработать запрос из-за внутренней ошибки, связанной с базой данных.

Пример: Клиент отправляет:

POST /api/user HTTP/1.1  

Host: example.com  

Content-Type: application/json  

{

    "name": "John Doe",

    "email": "john@example.com"

}

Сервер пытается выполнить:

INSERT INTO users (name, email) VALUES ('John Doe', 'john@example.com')

Но база данных возвращает ошибку, например:

Duplicate entry 'john@example.com' for key 'email_unique'

Сервер возвращает:

HTTP/1.1 500 Internal Server Error  

Content-Type: application/json  

{

    "error": "Internal Server Error. Database constraint violation."

}

Как проверить:

  1. Убедитесь, что данные не нарушают уникальные ограничения базы (например, уникальные ключи).

  2. Проверьте, правильно ли составлен SQL-запрос.

Последствия:

  • Запрос не выполняется.

  • Клиент получает общую ошибку сервера.

Возможные статус-коды:

  • 500 Internal Server Error.

 

2. Сервер не может соединиться с базой данных

Проблема: Сервер не может установить соединение с базой данных.

Пример: Клиент отправляет:

GET /api/products HTTP/1.1  

Host: example.com  

Сервер пытается подключиться:

Connection to database failed: Host not found.

Сервер возвращает:

HTTP/1.1 500 Internal Server Error  

Content-Type: application/json  

{

    "error": "Database connection failed."

}

Как проверить:

  1. Проверьте состояние базы данных (работает ли она).

  2. Убедитесь, что сервер имеет доступ к базе (правильные настройки хоста, порта, логина и пароля). Делает это DevOps или разработчик, а вы просто можете предложить вариант посмотреть.

Последствия:

  • Сервер не может обработать запрос.

  • Клиент получает ошибку подключения.

Возможные статус-коды:

  • 500 Internal Server Error.

 

3. SQL-запрос выполняется некорректно

Проблема: Запрос к базе данных содержит синтаксическую ошибку.

Пример: Клиент отправляет:

GET /api/orders HTTP/1.1  

Host: example.com  

Сервер выполняет:

SELECT * FORM orders

Ошибка в SQL:

You have an error in your SQL syntax near 'FORM orders'.

Сервер возвращает:

HTTP/1.1 500 Internal Server Error  

Content-Type: application/json  

{

    "error": "Database query failed."

}

Как проверить:

  1. Проверьте синтаксис SQL-запроса.

  2. Убедитесь, что запрос корректно формируется в коде сервера.

Последствия:

  • Данные не возвращаются.

  • Клиент получает сообщение о внутренней ошибке сервера.

Возможные статус-коды:

  • 500 Internal Server Error.

 

4. Сервер обращается к несуществующей таблице или колонке

Проблема: Сервер пытается выполнить запрос к базе, но указанная таблица или колонка не существует.

Пример: Клиент отправляет:

GET /api/invoices HTTP/1.1  

Host: example.com  

Сервер выполняет:

SELECT * FROM invoices

Ошибка базы:

Table 'invoices' doesn't exist.

Сервер возвращает:

HTTP/1.1 500 Internal Server Error  

Content-Type: application/json  

{

    "error": "Database table not found."

}

Как проверить:

  1. Проверьте существование таблицы или колонки в базе данных.

  2. Убедитесь, что запрос сформирован корректно.

Последствия:

  • Клиент получает ошибку сервера.

  • Запрос не выполняется.

Возможные статус-коды:

  • 500 Internal Server Error.

 

5. Некорректные данные возвращаются из базы данных

Проблема: Сервер возвращает данные, но они некорректны из-за ошибки в запросе или неправильной обработки.

Пример: Клиент отправляет:

GET /api/users HTTP/1.1  

Host: example.com  

Сервер выполняет:

SELECT id, name FROM users

Ошибка в обработке:

  • Сервер забывает вернуть поле email.

Сервер возвращает:

HTTP/1.1 200 OK  

Content-Type: application/json  

[

    {

        "id": 1,

        "name": "John Doe"

    }

]

Ожидается:

HTTP/1.1 200 OK  

Content-Type: application/json  

[

    {

        "id": 1,

        "name": "John Doe",

        "email": "john@example.com"

    }

]

Как проверить:

  1. Сравните возвращённые данные с ожидаемым форматом.

  2. Убедитесь, что сервер корректно формирует запрос к базе и обрабатывает ответ.

Последствия:

  • Клиент не получает необходимых данных.

  • Функционал приложения нарушается.

Возможные статус-коды:

  • 200 OK, но данные некорректны.

 

6. Взаимодействие с несколькими базами или сервисами

Проблема: Сервер отправляет запросы в несколько баз данных или сервисов, но один из них недоступен.

Пример: Клиент отправляет:

POST /api/checkout HTTP/1.1  

Host: example.com  

Content-Type: application/json  

{

    "cartId": 12345

}

Сервер выполняет:

  1. Запрос к базе cart для получения содержимого корзины.

  2. Запрос к базе inventory для проверки доступности товаров.

  3. Один из запросов возвращает ошибку:

Connection to database 'inventory' timed out.

Сервер возвращает:

HTTP/1.1 500 Internal Server Error  

Content-Type: application/json  

{

    "error": "Failed to complete checkout process. Try again later."

}

Как проверить:

  1. Убедитесь, что все базы данных или сервисы доступны.

  2. Проверьте, правильно ли настроена логика обработки зависимостей.

Последствия:

  • Операция не выполняется.

  • Клиент получает сообщение об ошибке.

Возможные статус-коды:

  • 500 Internal Server Error
