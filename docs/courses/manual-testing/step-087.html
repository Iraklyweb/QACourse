Лекция «Заголовки ответа в API»

 

Когда сервер отвечает на запрос клиента, он использует заголовки ответа, чтобы передать дополнительную информацию. Заголовки помогают клиенту правильно обрабатывать данные, обеспечивают безопасность, управляют кэшированием, сессиями и информируют тестировщика о возможных ошибках.

Знание заголовков ответа важно для тестировщика, так как они позволяют выявлять проблемы с форматом данных, кэшированием, авторизацией и доступом к API.

 

Как формируются заголовки ответа?

Сервер автоматически формирует заголовки ответа на основе запроса клиента, настроек API и бизнес-логики системы.

Пример HTTP-ответа сервера с заголовками:

HTTP/1.1 200 OK  

Content-Type: application/json  

Content-Length: 1234  

Set-Cookie: sessionId=xyz456; HttpOnly; Secure  

Cache-Control: no-cache  

Server: nginx/1.19.10  

В этом ответе заголовки передают информацию о формате данных, размере ответа, управлении сессиями и кэшированием.

 

Где увидеть заголовки ответа?

Заголовки ответа можно посмотреть в инструментах для тестирования API:

  • В браузере (DevTools → вкладка "Сеть")

  • В Postman (раздел Headers в ответе сервера)

  • В терминале (cURL, например curl -I)

Пример просмотра заголовков через curl:

curl -I https://example.com/api/users

Этот запрос вернёт только заголовки ответа без тела.

 

Как понять, что заголовки правильные?

Чтобы убедиться, что сервер корректно формирует заголовки, тестировщик проверяет:

  • Соответствие формату API — например, Content-Type должен совпадать с реальным форматом данных.

  • Правильность работы кэширования — сервер должен корректно управлять Cache-Control и ETag.

  • Работу сессий и безопасности — Set-Cookie должен устанавливать корректные флаги (HttpOnly, Secure).

  • Редиректы и обработку ошибок — при кодах 301, 302 заголовок Location должен указывать правильный URL.

 

Группы заголовков ответа

Формат данных

Эти заголовки описывают, в каком формате возвращаются данные и сколько их.

Content-Type — указывает формат возвращаемых данных. Пример:

Content-Type: application/json

Тестировщик проверяет, что сервер всегда возвращает данные в ожидаемом формате.

Content-Length — сообщает размер тела ответа в байтах. Пример:

Content-Length: 1234

Используется для проверки полноты ответа.

 

Кэширование

Заголовки управляют тем, как клиент должен кэшировать данные.

Cache-Control — задаёт правила кэширования. Пример:

Cache-Control: no-cache

Если указано no-cache, клиент должен запрашивать свежие данные, а не использовать закэшированные.

ETag — уникальный идентификатор версии ресурса. Пример:

ETag: "abc123etag"

Если ETag совпадает с предыдущим значением, клиент может использовать закэшированные данные.

 

Безопасность и сессии

Эти заголовки обеспечивают защиту API и управление сессиями.

Set-Cookie — передаёт клиенту данные сессии. Пример:

Set-Cookie: sessionId=xyz456; HttpOnly; Secure

Сервер устанавливает сессию, а клиент затем отправляет её обратно в заголовке Cookie:

Cookie: sessionId=xyz456

Тестировщик проверяет, что:

  • Куки устанавливаются корректно.

  • Сервер правильно обрабатывает запросы с переданным Cookie.

  • Присутствуют флаги безопасности (HttpOnly, Secure).

Access-Control-Allow-Origin — указывает, какие источники могут обращаться к API. Пример:

Access-Control-Allow-Origin: *

Если указано *, API доступен с любых доменов, что может быть небезопасно.

 

Информация о сервере

Эти заголовки предоставляют сведения о сервере и управляют перенаправлением.

Server — передаёт информацию о сервере, обработавшем запрос. Пример:

Server: nginx/1.19.10

Обычно этот заголовок не тестируется, но может быть полезен для анализа конфигурации.

Location — указывает, куда перенаправлять клиента при редиректах. Пример:

Location: https://example.com/new-page

Тестировщик проверяет, что при кодах 301 Moved Permanently и 302 Found клиент действительно перенаправляется на новый URL.

 

Как понять работу заголовков?

Set-Cookie и Cookie: работа сессий Сервер устанавливает сессию через Set-Cookie, а клиент отправляет её обратно через Cookie. Это основа авторизации и сессионного хранения данных.

Content-Type и Content-Length: контроль данных Они обеспечивают корректную передачу данных клиенту, указывая их формат и размер.

Cache-Control и ETag: управление кэшем Эти заголовки определяют, нужно ли клиенту загружать новые данные или использовать закэшированные.

 

Какие заголовки тестирует тестировщик?

На практике тестировщик проверяет:

  • Set-Cookie и Cookie — работа сессий и авторизации.

  • Content-Type и Content-Length — корректность формата и размера данных.

  • Cache-Control и ETag — правильная работа кэширования.

  • Access-Control-Allow-Origin — контроль разрешённых источников API.

  • Location — корректность редиректов.

Остальные заголовки тестируются по необходимости, в зависимости от специфики API.

 

Итог

Заголовки ответа помогают клиенту правильно обрабатывать полученные данные, управляют кэшированием, безопасностью и сессиями.

Тестировщик чаще всего работает с Set-Cookie, Content-Type, Cache-Control и Location, проверяя корректность авторизации, передачи данных и кэширования. Остальные заголовки используются реже, но понимание их работы помогает эффективнее тестировать API.
