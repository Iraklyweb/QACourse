Лекция «Структура сообщения в API»

 

Когда клиент и сервер взаимодействуют через API, они обмениваются сообщениями. Сообщение — это способ передать данные или запросить информацию. Клиент "спрашивает", а сервер "отвечает". Чтобы разобраться, как это работает, важно понять, из чего состоит каждое сообщение.

 

Стартовая строка (Request Line / Status Line)

Это первая строка сообщения, которая зависит от того, является ли оно запросом или ответом.

В HTTP-запросе (Request Line) указывается метод, путь к ресурсу и версия протокола. Пример:

POST /api/users HTTP/1.1

  • POST — HTTP-метод (например, создание данных).

  • /api/users — путь к ресурсу.

  • HTTP/1.1 — версия протокола.

В HTTP-ответе (Status Line) содержится версия протокола, код состояния и описание ответа. Пример:

HTTP/1.1 200 OK

  • HTTP/1.1 — версия протокола.

  • 200 — код состояния (означает успешный запрос).

  • OK — текстовое описание.

 

Заголовки (Headers)

Дополнительная информация (метаинформация), которая помогает клиенту и серверу понять, как обрабатывать сообщение.

Примеры заголовков:

  • Content-Type — формат данных (например, JSON или XML).

  • Authorization — ключ (токен) доступа.

  • Accept — в каком формате клиент хочет получить ответ.

Пример заголовков:

Content-Type: application/json  

Authorization: Bearer abc123token

Accept: application/json

 

Тело сообщения (Body)

Основная часть запроса или ответа, содержащая передаваемые данные. Используется не во всех случаях — например, у запросов GET тело обычно отсутствует, так как такие запросы предназначены только для получения информации, а не для её передачи.

Тело — это данные, которые передаются между клиентом и сервером. Оно необязательно и используется только тогда, когда нужно отправить дополнительные данные.

  • В запросах клиент может передавать в теле логин, пароль, параметры заказа и т.д.

  • В ответах сервер возвращает данные, которые запросил клиент (например, информацию о пользователе).

Пример тела запроса:

{

  "username": "test_user",

  "password": "123456"

}

Пример тела ответа:

{

  "userId": 1,

  "username": "test_user",

  "status": "active"

}

 

Ошибки (Fault / Status Codes)

Содержат информацию о том, что пошло не так.

Если сервер не смог обработать запрос, он отправит код ошибки. Например:

HTTP/1.1 404 Not Found

  • 404 — код ошибки (ресурс не найден).

  • Not Found — текстовое описание ошибки.

В SOAP API ошибки передаются в теле ответа внутри блока <Fault>. Пример:

<Fault>

    <faultcode>Client</faultcode>

    <faultstring>Invalid request</faultstring>

</Fault>

Запросы и ответы: Сообщения делятся на:

  • Запросы: то, что отправляет клиент, чтобы запросить информацию или выполнить действие. Например, запрос на создание пользователя.

  • Ответы: то, что возвращает сервер, чтобы сообщить клиенту результат (например, данные пользователя или статус выполнения действия).

 

Зачем понимать структуру сообщений?

Знание структуры API-сообщений помогает правильно отправлять данные и анализировать ответы.

Основные задачи:

  • Поиск ошибок — если API не работает, можно быстро понять, в чём проблема: неправильный заголовок, некорректный формат тела запроса или ошибка сервера.

  • Тестирование — проверка, соответствуют ли ответы API ожиданиям, правильные ли коды состояния и данные в теле ответа.

 

Итог

Сообщение в API состоит из стартовой строки, заголовков, тела (если нужно) и может содержать ошибки. Разделение на запросы и ответы помогает понять, как API работает. Это знание важно при тестировании и работе с API, но в реальности большинство запросов можно воспринимать просто как URL с параметрами и телом.

 

 

Что нужно уметь рассказать
– Сообщение = обмен данными между клиентом и сервером
– Стартовая строка:
 • В запросе: метод + путь + версия протокола (пример: POST /api/users HTTP/1.1)
 • В ответе: версия протокола + код состояния + описание (пример: HTTP/1.1 200 OK)
– Заголовки (Headers): метаинформация (Content-Type, Authorization, Accept)
– Тело (Body): данные запроса или ответа, может отсутствовать (GET без тела)
– Ошибки (Fault / Status Codes): передаются кодом статуса (404 Not Found) или в SOAP через <Fault>
– Запросы = то, что отправляет клиент
– Ответы = то, что возвращает сервер
