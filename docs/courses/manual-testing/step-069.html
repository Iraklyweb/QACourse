Лекция «Как это работает в HTTPS?»

 

  1. Установка соединения: Когда клиент подключается к серверу, они сначала договариваются о правилах шифрования. Это называется "рукопожатие" (handshake). Во время этого:

    • Клиент проверяет, что сервер настоящий (проверяет SSL/TLS-сертификат).

    • Стороны обмениваются ключами для шифрования, чтобы никто не смог перехватить или изменить передаваемые данные.

  2. Шифрование данных: После "рукопожатия" всё, что отправляется между клиентом и сервером, зашифровано. Например:

    • Если клиент отправляет пароль, вместо "mypassword123" сервер получает "cG5!@#sf83zq", который он расшифрует с помощью своего ключа.

    • Аналогично, если сервер отправляет данные клиенту, они тоже шифруются перед отправкой.

  3. Никто не может подслушать: Даже если кто-то в сети перехватит данные, они увидят только зашифрованный "мусор", который невозможно прочитать без ключей, известных только клиенту и серверу.

 

Улучшение понимания: короткий пример

Представь, что ты отправляешь сообщение другу через закрытый конверт с особым кодовым замком.

  • Только ты и друг знаете, как открыть этот замок (это ваши "ключи").

  • Даже если кто-то перехватит конверт, он не сможет открыть его и прочитать содержимое без знания кода.

HTTPS работает по тому же принципу: только клиент и сервер знают код доступа (ключи), а любые попытки вмешательства становятся бессмысленными.
