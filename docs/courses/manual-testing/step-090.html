Лекция «HTTP-статус-коды 300: перенаправления»

 

Статус-коды группы 300 сигнализируют клиенту, что для выполнения запроса нужно предпринять дополнительные действия. Обычно это перенаправление на другой ресурс или работа с кэшированными данными. Хотя с ними тестировщики работают реже, важно понимать их логику, чтобы проверять редиректы и оптимизацию запросов.

 

Что это значит?

Коды группы 300 используются для управления ресурсами, кэширования и перенаправления запросов. Эти коды помогают серверу:

  • Указать клиенту, что ресурс перемещён.

  • Сообщить, что ресурс доступен по нескольким адресам.

  • Сэкономить трафик, используя кэшированную версию.

Такие коды могут быть связаны с методами GET, POST и HEAD. Чаще всего такие коды встречаются при выполнении GET-запросов.

 

 

Как получить 300 и его комбинации?

301 Moved Permanently

Что это значит? Ресурс был перемещён на постоянной основе. Клиент должен использовать новый URL для всех будущих запросов.

Пример для GET: Клиент запрашивает старый URL, который был перенаправлен:

GET /old-path HTTP/1.1

Host: example.com

Ответ:

301 Moved Permanently

Location: /new-path

Теперь клиент должен использовать /new-path для всех будущих запросов.

Где это встречается?

  • При миграции сайта на новый домен.

  • При изменении структуры URL.

 

302 Found

Что это значит? Ресурс временно доступен по другому адресу. В отличие от 301, клиент продолжает использовать исходный URL в будущем.

Пример для временного перенаправления:

GET /maintenance HTTP/1.1

Host: example.com

Ответ:

302 Found

Location: /temporary-path

Клиент перенаправляется на /temporary-path, но в будущем может использовать старый URL.

Где это встречается?

При временной модификации ресурса (например, страница технического обслуживания).

 

304 Not Modified

Что это значит? Сервер сообщает, что ресурс не изменился с момента последнего запроса. Это сокращает объём передаваемых данных, так как клиент может использовать кэшированную версию.

Пример для кэширования: Клиент отправляет запрос с заголовком If-Modified-Since, чтобы проверить, обновился ли ресурс:

GET /products HTTP/1.1

Host: example.com

If-Modified-Since: Wed, 15 Nov 2023 10:00:00 GMT

Ответ:

304 Not Modified

Клиент использует локальную копию ресурса.

Где это встречается?

При использовании кэширования для оптимизации запросов.

 

307 Temporary Redirect

Что это значит? Ресурс временно перемещён, но клиент должен повторить запрос с тем же HTTP-методом.

Пример для POST-запроса:

POST /api/v1/process HTTP/1.1

Host: example.com

Content-Type: application/json

{

  "task": "generate-report"

}

Ответ:

307 Temporary Redirect

Location: /api/v2/process

Клиент перенаправляется на /api/v2/process, сохраняя метод POST.

Где это встречается?

При временной модификации маршрута API, чтобы указать новый путь.

 

308 Permanent Redirect

Что это значит? Ресурс перемещён на постоянной основе, и клиент должен использовать новый URL. Как и 307, сохраняет исходный HTTP-метод.

Пример для PUT-запроса:

PUT /old-path HTTP/1.1

Host: example.com

Content-Type: application/json

{

  "name": "Updated Resource"

}

Ответ:

308 Permanent Redirect

Location: /new-path

Клиент перенаправляется на /new-path, сохраняя метод PUT.

Где это встречается?

При долгосрочной миграции API, где важно сохранить исходный метод.

 

Ошибки использования

  1. Неправильные редиректы:

    • Если сервер настроен некорректно, это может привести к зацикливанию редиректов (например, /path1 перенаправляет на /path2, а /path2 — обратно на /path1).

  2. Неправильный статус-код:

    • Например, сервер может вернуть 302 Found, даже если ресурс был перемещён навсегда.

  3. Отсутствие заголовков для кэширования:

    • Если клиент получает 304 Not Modified, но кэшированные данные отсутствуют, это указывает на проблему с заголовками.

 

Логика работы с кэшированием

Статус-код 304 Not Modified работает только в связке с заголовками запроса, такими как If-Modified-Since или ETag. Это помогает:

  • Снизить нагрузку на сервер.

  • Ускорить загрузку страниц за счёт использования локальных данных.

Однако, если сервер неверно обрабатывает кэш, это может привести к тому, что клиент будет использовать устаревшую информацию.

 

Рекомендательный характер

Как и другие статус-коды, коды группы 300 носят рекомендательный характер. Например:

  • Вместо 301 Moved Permanently сервер может вернуть 302 Found, даже если перемещение постоянное.

  • Некоторые серверы вообще не используют коды 3xx для перенаправления, полагаясь на JavaScript или другие клиентские технологии.

Тестировщикам важно проверять, соответствует ли поведение сервера ожиданиям, и фиксировать любые отклонения.

 

Почему это важно понимать?

Коды группы 300 важны, потому что они помогают:

  • Проверять правильность редиректов.

  • Убедиться, что кэширование данных работает корректно.

  • Оптимизировать взаимодействие между клиентом и сервером.

Хотя тестировщики редко сталкиваются с кодами 300 в повседневной работе, понимание их логики поможет лучше разбираться в устройстве API и эффективнее проверять системы.
