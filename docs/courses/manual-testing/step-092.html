Лекция «HTTP-статус-коды 500: серверные ошибки»

 

Статус-коды группы 500 указывают на то, что запрос клиента был корректным, но сервер не смог его обработать из-за внутренней ошибки. Такие коды важны для тестировщиков, так как они часто сигнализируют о проблемах в работе системы, которые нужно уметь диагностировать и передавать разработчикам.

 

Что это значит?

Серверные ошибки возникают, когда запрос клиента не может быть выполнен из-за сбоя в логике, инфраструктуре или ограничениях серверной стороны. Это может быть:

  • Ошибки в коде сервера.

  • Проблемы взаимодействия с базой данных или сторонними сервисами.

  • Превышение лимитов ресурсов (память, процессорное время).

Тестировщикам важно понимать, что коды 500 сигнализируют именно о сбое на стороне сервера, а не клиента.

 

Основные коды 500 и как их получить

500 Internal Server Error

Что это значит? Общая ошибка сервера, которая возникает, когда он не может выполнить запрос из-за внутреннего сбоя. Это "универсальный" код для любых ситуаций, которые сервер не может обработать корректно.

Как получить?

Отправьте запрос, который вызывает непредвиденное поведение на сервере.

Пример:

GET /products?id=abc HTTP/1.1

Host: example.com

Если сервер не обрабатывает некорректный идентификатор должным образом, он может вернуть: 500 Internal Server Error

{

  "error": "Unexpected error occurred"

}

Где это встречается?

  • Ошибки в бизнес-логике на сервере.

  • Проблемы с обработкой данных или отсутствием валидации.

 

502 Bad Gateway

Что это значит? Этот код указывает, что сервер (шлюз) получил некорректный или неполный ответ от другого сервера, к которому он обращается.

Как получить?

Отправьте запрос через прокси-сервер или балансировщик нагрузки, где один из бэкэндов недоступен. Пример:

GET /api/resource HTTP/1.1

Host: example.com

Ответ: 502 Bad Gateway

{

  "error": "Invalid response from upstream server"

}

Где это встречается?

  • В системах с несколькими серверами, где один из них не отвечает.

  • Когда внешние зависимости, такие как сторонние API, недоступны.

 

503 Service Unavailable

Что это значит? Сервер временно недоступен для обработки запросов, обычно из-за перегрузки, технического обслуживания или других временных проблем.

Как получить?

Отправьте запрос на сервер, который превышает свои лимиты. Пример:

GET /heavy-load HTTP/1.1

Host: example.com

Ответ: 503 Service Unavailable

{

  "error": "The server is temporarily unable to handle the request"

}

Где это встречается?

  • При перегрузке сервера, например, в условиях нагрузочного тестирования или пиковых нагрузок.

  • Когда сервер отключён на время технического обслуживания.

 

504 Gateway Timeout

Что это значит? Этот код указывает, что сервер (шлюз) не дождался ответа от другого сервера в установленное время.

Как получить?

Отправьте запрос, который обрабатывается слишком долго (например, запрос к внешнему API с задержкой). Пример:

GET /slow-service HTTP/1.1

Host: example.com

Ответ: 504 Gateway Timeout

{

  "error": "Upstream server timeout"

}

Где это встречается?

  • При медленной работе базы данных или сторонних сервисов.

  • Когда сервер настроен с коротким временем ожидания (timeout).

 

Рекомендательный характер

Как и коды других групп, серверные ошибки не всегда строго соответствуют стандартам. Например:

  • Сервер может возвращать 500 Internal Server Error вместо более специфических кодов (502, 503), если разработчики не предусмотрели отдельные обработки для каждого случая.

  • Иногда сервер возвращает 503 Service Unavailable во время перегрузки, хотя проблема связана с ошибкой логики, которая больше подходит для 500.

 

Как тестировщик может диагностировать ошибки 500?

  1. Сознательно вызывайте ошибки: Как и с кодами 400, тестировщик должен уметь искусственно создавать сценарии, которые приводят к кодам 500. Например:

    • Отправляйте запросы с некорректными данными.

    • Используйте инструменты для перегрузки сервера (нагрузочное тестирование).

  2. Используйте инструменты: Такие инструменты, как Postman, Insomnia или системы мониторинга (например, Kibana, Grafana), помогут отследить, где именно произошла ошибка, и получить больше информации.

  3. Работайте с логами: Большинство серверов записывают внутренние ошибки в логи. Передайте эти логи разработчикам, чтобы они могли диагностировать проблему.

 

Почему это нужно понимать?

Статус-коды группы 500 не только помогают обнаруживать сбои, но и учат:

  • Как API справляется с внутренними ошибками.

  • Какие ограничения и уязвимости есть в системе.

  • Как правильно передавать информацию о сбоях разработчикам.

Ваша задача — не только зафиксировать проблему, но и понять её контекст, чтобы помочь команде исправить её быстро и эффективно.
