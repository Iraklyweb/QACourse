Лекция «API в клиент-серверной архитектуре: примеры на основе трёхзвенной системы»

 

Что здесь происходит?

Когда ты взаимодействуешь с любым приложением — будь то доставка еды или прогноз погоды, — между клиентом (то есть приложением на твоём устройстве) и сервером происходит общение. API — это те самые договорённости, с помощью которых клиент и сервер понимают друг друга. А теперь разберём это на примерах, чтобы стало понятно, где клиент, где сервер и как это связано с базой данных.

 

Пример 1: Ресторанное приложение

Ситуация: Ты хочешь посмотреть меню ресторана.

  1. Клиент: Это твоё приложение доставки еды. Ты открываешь ресторан, и приложение обращается к серверу со словами: "Дай мне меню этого ресторана".

  2. Сервер: Это то место, где хранится логика приложения. Сервер принимает запрос от клиента, проверяет, какой именно ресторан ты выбрал, и понимает, что нужно для него достать меню.

  3. База данных: Сервер "идёт" в базу данных, где хранится информация обо всех ресторанах и их меню, и забирает нужные данные для выбранного ресторана.

  4. Сервер отвечает: Получив меню из базы данных, сервер упаковывает эту информацию в удобный формат и отправляет её клиенту.

  5. Клиент показывает результат: Приложение получает данные и показывает тебе на экране: Пицца — 500 рублей, Салат — 300 рублей.

 

Пример 2: Приложение для погоды

Ситуация: Ты хочешь узнать погоду в своём городе.

  1. Клиент: Это твоё приложение погоды. Ты вводишь название города, например "Москва". Приложение формирует запрос к серверу: "Дай мне данные о погоде для Москвы".

  2. Сервер: Сервер принимает запрос, анализирует, какой город указан, и понимает, что нужно получить информацию о погоде в Москве.

  3. База данных: Сервер либо запрашивает данные из своей базы данных (если информация о погоде недавно обновлялась), либо обращается к внешнему сервису, который предоставляет свежие данные о погоде.

  4. Сервер отвечает: Получив данные о температуре, состоянии неба и скорости ветра, сервер передаёт эту информацию обратно приложению.

  5. Клиент показывает результат: Приложение получает ответ и выводит его в удобном виде, например: "В Москве сейчас -5°C, облачно, ветер 10 м/с".

 

Как это связано с API?

API — это посредник между клиентом и сервером. Клиент отправляет запрос через API: "Мне нужны такие-то данные". API помогает серверу понять, что именно нужно сделать, и упаковывает ответ, чтобы клиент смог его "прочитать". Без API клиент и сервер просто не смогли бы договориться, как общаться.

 

Итог

  1. Клиент — это то, что работает на твоём устройстве: приложение, которое ты видишь и с которым взаимодействуешь. (приложение на телефоне или сайте, а так же может быть другой сервер).

  2. Сервер — это "мозг", который принимает запросы, выполняет логику и обрабатывает данные.

  3. База данных — это место, где всё хранится (меню ресторанов, данные о погоде и так далее).

  4. API — это мост между клиентом и сервером, который позволяет этим частям системы взаимодействовать.
