Лекция «Пример справочного значения»

 

В API есть запрос на создание питомца, где поле species (вид животного) должно содержать только допустимые значения из списка.

Пример допустимых значений (справочник):

{

  "species": ["cat", "dog", "rabbit", "parrot"]

}

 

Правильные данные:

{

  "id": 1,

  "name": "Барсик",

  "species": "cat"

}

Значение "cat" есть в справочнике — API обработает запрос.

 

Ошибка при передаче несуществующего значения:

{

  "id": 1,

  "name": "Барсик",

  "species": "фывфы"

}

Значение "фывфы" не входит в список допустимых значений, поэтому API должно вернуть ошибку. Просто ввести любое значение, которого нет в справочнике, не обязательно что-то осмысленное вводить.

 

Где используются справочные значения?

  1. Категории товаров, статусы заказов

    • status: ["new", "processing", "completed", "cancelled"]

  2. Роли пользователей

    • role: ["admin", "user", "moderator"]

  3. Типы документов

    • document_type: ["passport", "driver_license", "id_card"]

  4. Языки интерфейса

    • language: ["ru", "en", "de", "fr"]

 

Как тестировать справочные значения?

Позитивные тесты:

  • Отправить запрос со всеми корректными значениями из справочника в первый раз, когда проверяете. в будущем достаточно только 1 раза. Используется техника тест дизайна “класс эквивалентности”

  • Проверить, что API принимает данные и возвращает правильный ответ.

Негативные тесты:

  • Передать несуществующее значение ("species": "dinosaur" или “ыав”) и проверить, что API возвращает ошибку.

  • Отправить "species": "" (пустое значение) и проверить реакцию API.

  • Отправить "species": null и убедиться, что API либо возвращает ошибку, либо применяет значение по умолчанию (если предусмотрено).

 

Зачем это нужно?

  • Позволяет контролировать вводимые данные и исключать ошибки.

  • Гарантирует, что в базе не появятся невалидные данные.

  • Упрощает обработку данных на сервере — API не нужно разбирать каждое значение отдельно, достаточно сверить его со справочником.

Справочные значения помогают стандартизировать работу API и избежать проблем с некорректными данными.
