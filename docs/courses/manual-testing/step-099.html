Лекция «Метод DELETE: как работает и зачем нужен»

 

DELETE является идемпотентным

  • Повторный DELETE-запрос не создаст дубликатов и не изменит состояние, если ресурс уже удалён.

  • Однако, если API поддерживает мягкое удаление (soft delete), каждый запрос может менять статус объекта (deleted=true).

Влияние на безопасность и состояние сервера

  • DELETE изменяет состояние сервера, так как удаляет существующий ресурс. Тем самым DELETE небезопасен с точки зрения изменения данных на сервере.

  • Небезопасен с точки зрения передачи данных, так как они передаются в URL, а URL не шифруется.

  • Как и другие методы изменения данных, DELETE требует авторизации, если ресурс защищён.

  • Некоторые API требуют дополнительного подтверждения перед удалением (например, DELETE-запрос может быть защищён токенами или ролями).

Передача данных

  • DELETE обычно не имеет тела запроса, так как указание удаляемого объекта происходит через URL.

  • Однако некоторые API позволяют передавать дополнительные параметры (например, причину удаления).

Ограничения длины URL отсутствуют

  • DELETE-запросы передают данные через URL, а не в теле, поэтому их длина не ограничена, кроме стандартных ограничений браузеров и серверов.

Форматы данных

  • DELETE чаще всего не возвращает данные, но может отправлять JSON с подтверждением: { "status": "deleted" }

  • Некоторые API поддерживают мягкое удаление (soft delete) и возвращают обновлённое состояние объекта: { "id": 1, "deleted": true }

Кэширование

  • DELETE не кэшируется, так как он изменяет состояние сервера.

  • Браузеры и прокси-серверы не сохраняют результаты DELETE-запросов.

 

Дополнительные особенности метода DELETE

DELETE требует проверки существования ресурса

  • Если объект уже удалён, сервер может вернуть 404 Not Found.

  • Некоторые API не проверяют существование ресурса и просто отправляют 204 No Content.

DELETE работает на уровне конкретного ресурса

  • Запрос выполняется на конкретный объект (/users/1).

  • В отличие от PUT и PATCH, которые могут обновлять данные, DELETE только удаляет.

DELETE может быть логическим или физическим

  • Физическое удаление – данные стираются навсегда.

  • Логическое удаление – запись остаётся в базе, но получает статус deleted=true, что позволяет восстановить её при необходимости.

DELETE используется, когда нужно навсегда или временно удалить ресурс

  • Повторные DELETE-запросы не должны изменять систему, если ресурс уже удалён.

 

Итог

Метод DELETE используется для удаления ресурса и может быть как физическим (перманентным), так и логическим (soft delete). В отличие от GET, который только читает данные, DELETE изменяет состояние сервера.

 

Как тестируют DELETE?

  • Если есть доступ к БД, проверяют, действительно ли объект удалился.

  • Если доступа к БД нет, делают GET-запрос после DELETE, чтобы убедиться, что сервер вернёт 404 Not Found.

  • Проверяют, возвращает ли сервер корректные статус-коды (204 No Content, 200 OK, 404 Not Found, 403 Forbidden).

  • Тестируют повторные запросы:

    • Первый DELETE должен удалить объект.

    • Последующие не должны изменять состояние (если API идемпотентное).

DELETE — это метод, который нельзя откатить, поэтому его использование требует осторожности. Если API поддерживает мягкое удаление, важно проверять изменение статуса ресурса вместо его полного исчезновения.
