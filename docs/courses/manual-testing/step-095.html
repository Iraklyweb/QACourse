Лекция «Метод GET: как работает и зачем нужен»

 

Метод GET используется для запроса данных с сервера без их изменения. Если сравнивать с реальной жизнью, GET — это как просмотр каталога товаров в интернет-магазине: вы можете видеть список товаров, но не можете его изменить.
 

Как работает GET?

Метод GET позволяет клиенту получать данные без изменения ресурса. В отличие от POST, который отправляет данные на сервер, GET только запрашивает информацию.

  1. Клиент отправляет GET-запрос: Клиент указывает URL ресурса, который хочет получить. Если требуется уточнение, добавляет query-параметры.

Пример запроса:
GET /users?role=admin HTTP/1.1  
Host: api.example.com  
Этот запрос получает список пользователей с ролью администратора.

  1. Сервер обрабатывает запрос:

  • Проверяет, существует ли ресурс (/users).

  • Фильтрует данные, если переданы параметры (например, role=admin).

  • Формирует ответ с найденными данными.

  1. Сервер отправляет ответ, который включает:

  • Статус-код (например, 200 OK, если запрос успешен).

  • Заголовки, указывающие тип данных (Content-Type).

  • Тело ответа, содержащее запрашиваемую информацию.

Пример ответа:
HTTP/1.1 200 OK  
Content-Type: application/json  
[
  {"id": 1, "name": "Alice"},
  {"id": 2, "name": "Bob"}
]
Сервер отправляет коды ответа:

  • 200 OK — запрос успешен, сервер возвращает данные.

  • 204 No Content — запрос успешен, но данных нет.

  • 400 Bad Request — некорректный запрос.

  • 404 Not Found — запрашиваемый ресурс не найден.

Метод GET удобен, когда нужно просто получить данные, не внося изменений на сервере.

 

Основные свойства метода GET

GET является идемпотентным

  • Повторный запрос с одинаковыми параметрами всегда возвращает один и тот же результат, если данные на сервере не изменялись.

Влияние на безопасность и состояние сервера

  • GET не изменяет состояние сервера, а лишь запрашивает данные для их чтения, что делает его безопасным методом.

  • Однако сам факт обращения к серверу может быть зафиксирован (например, в логах или счётчиках посещений).

  • GET небезопасен для передачи конфиденциальных данных, так как параметры передаются в URL и могут быть:

    • Видны в истории браузера.

    • Записаны в логи сервера.

    • Кэшироваться прокси-серверами.

Передача данных

  • GET не использует тело запроса, вся информация передаётся в URL в виде query-параметров.

  • Это делает запросы лёгкими, но может ограничивать их длину.

Ограничение длины URL

  • URL имеет ограниченную длину, которая зависит от браузера и сервера (обычно до 2048 символов).

  • Если передаётся слишком много данных, запрос может не обработаться.

  • В таких случаях лучше использовать метод POST, где данные передаются в теле запроса.

Форматы данных

  • Чаще всего GET-запрос возвращает данные в JSON, так как REST API работают с этим форматом.

  • Может также поддерживать XML, HTML, CSV, в зависимости от API.

Кэширование

  • GET-запросы кэшируются браузерами и прокси-серверами, если сервер не запретил это заголовками Cache-Control или ETag.

  • Это позволяет сократить количество запросов, но может привести к получению устаревших данных.

 

Дополнительные особенности GET

GET требует существования ресурса

  • Если объект найден, сервер возвращает 200 OK и данные.

  • Если объект не найден, сервер возвращает 404 Not Found.

GET всегда выполняется для конкретного ресурса
Например, получение списка пользователей: GET /users  
Или получение конкретного пользователя: GET /users/1  
GET удобен, когда требуется только получение данных

  • Он не создаёт, не изменяет и не удаляет информацию.

  • Если необходимо передать большие объёмы данных или работать с конфиденциальной информацией, лучше использовать другие методы.

 

Параметры в GET-запросах

Метод GET передаёт параметры через строку запроса (query string) в URL. Это позволяет уточнять запрос и получать только нужные данные.
Как выглядит строка запроса?
Строка запроса начинается с символа ?, за которым следуют параметры в формате ключ=значение. Если параметров несколько, они разделяются символом &.
Пример:
GET /users?role=admin&status=active HTTP/1.1
Разберём этот запрос:

  • ? (вопросительный знак) — это символ, который указывает начало строки параметров в URL.

  • role — это ключ, который обозначает роль пользователя (например, администратор, пользователь, менеджер).

  • = — знак равенства, который связывает ключ и значение.

  • admin — значение, указывающее, что нам нужны пользователи с ролью администратора.

  • & (амперсанд) —  это разделитель, который используется для соединения нескольких параметров в URL, показывая, что один параметр следует за другим.

  • status — это ключ, который указывает на статус пользователя.

  • active — значение, обозначающее, что мы ищем только активных пользователей.

 

Типы параметров в GET-запросах

1. Параметры фильтрации Позволяют уточнять запрос, возвращая только нужные данные.
GET /products?category=electronics&price<1000
Этот запрос вернёт товары из категории "электроника" с ценой до 1000.

 

2. Параметры сортировки Определяют порядок вывода данных.
GET /products?sort=price&order=asc
Список товаров будет отсортирован по цене в порядке возрастания.

 

3. Параметры пагинации Когда данных много, сервер возвращает их постранично, чтобы снизить нагрузку.
GET /users?page=2&limit=10
Этот запрос вернёт вторую страницу списка пользователей, по 10 записей на каждой странице.

 

4. Специфические параметры API Некоторые API имеют свои особые параметры для управления запросами.
GET /search?q=API+testing&lang=en

  • q=API testing — строка поиска.

  • lang=en — указывает язык результатов.

 

Особенности работы с параметрами

1. Кодирование параметров Если параметры содержат пробелы, специальные символы или кириллицу, их нужно кодировать в формате URL. Как выглядит закодированное значение:

  • Пробел → %20

  • Кириллица (тест) → %D1%82%D0%B5%D1%81%D1%82

  • Символ + → %2B

Пример до кодирования:
GET /search?q=API testing
После кодирования:
GET /search?q=API%20testing

 

2. Порядок параметров Порядок параметров в строке запроса не имеет значения. Эти два запроса вернут одинаковый результат:
GET /users?role=admin&status=active
GET /users?status=active&role=admin
 

Итог

Метод GET – основной инструмент для запроса данных, но требует осторожности при передаче конфиденциальных данных и работе с длинными URL.
Как тестируют GET?

  1. Отправляют GET-запрос и проверяют, возвращает ли сервер нужные данные.

  2. Сравнивают полученные данные с ожидаемыми, проверяют корректность фильтрации, сортировки, пагинации.

  3. Проверяют обработку некорректных запросов (404 Not Found, 400 Bad Request).
