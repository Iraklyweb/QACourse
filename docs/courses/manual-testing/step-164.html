Лекция «Что означают уровни вложенности (1, 2, 3 уровни) в тестировании API?»

SQL · Практика

Когда в API передаются данные в формате JSON, они могут содержать вложенные структуры. Проверка таких структур требует тестирования разных уровней вложенности.

1 уровень вложенности

Данные передаются без вложенных объектов – это простая структура JSON.

Пример:

{

  "id": 1,

  "name": "Барсик",

  "age": 3

}

Здесь все поля находятся на первом уровне вложенности.

2 уровень вложенности

Данные содержат вложенный объект внутри основного.

Пример:

{

  "id": 1,

  "name": "Барсик",

  "age": 3,

  "owner": {

    "id": 10,

    "name": "Алексей"

  }

}

Поле owner содержит вложенный объект (2 уровень), который имеет свои поля.

3 уровень вложенности

Данные содержат несколько вложенных объектов, создавая более сложную структуру.

Пример:

{

  "id": 1,

  "name": "Барсик",

  "age": 3,

  "owner": {

    "id": 10,

    "name": "Алексей",

    "address": {

      "city": "Москва",

      "street": "Тверская",

      "building": 5

    }

  }

}

Здесь объект owner (2 уровень)  содержит ещё один вложенный объект address (3 уровень).

Зачем это нужно?

  • Позволяет проверить, как API обрабатывает разные уровни вложенности в JSON.

  • Позволяет выявить ошибки в обработке сложных объектов.

  • Помогает тестировать зависимые структуры данных.

Чем выше уровень вложенности, тем сложнее тест и больше вероятность обнаружить ошибки в обработке данных.
