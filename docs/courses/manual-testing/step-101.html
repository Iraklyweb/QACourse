Лекция «Метод OPTIONS: как работает и зачем нужен»

 

Метод OPTIONS используется для получения информации о возможностях сервера и поддерживаемых HTTP-методах для конкретного ресурса. В отличие от GET, POST или PUT, он не выполняет никаких операций с данными, а только сообщает, какие методы поддерживаются API.

Если сравнивать с реальной жизнью, OPTIONS — это как спросить у оператора техподдержки, какие услуги предоставляет компания, не заказывая ничего.

 

Как работает OPTIONS?

Метод OPTIONS позволяет клиенту узнать, какие HTTP-методы и заголовки поддерживает сервер для конкретного ресурса или всего API.

1. Клиент отправляет OPTIONS-запрос для конкретного ресурса:

OPTIONS /users HTTP/1.1  

Host: api.example.com  

→ Клиент спрашивает, какие методы доступны для /users.

2. Сервер обрабатывает запрос:

  • Проверяет, какие методы поддерживает данный ресурс.

  • Возвращает список допустимых HTTP-методов в заголовке Allow.

3. Сервер отправляет ответ:

HTTP/1.1 200 OK  

Allow: GET, POST, PUT, DELETE, OPTIONS  

Content-Length: 0  

→ В заголовке Allow указаны все методы, которые поддерживает ресурс.

4. OPTIONS-запрос для всех методов API:

OPTIONS * HTTP/1.1  

Host: api.example.com  

→ Этот запрос позволяет узнать общие правила API, а не конкретного ресурса.

5. Сервер может вернуть CORS-заголовки:

HTTP/1.1 204 No Content  

Access-Control-Allow-Methods: GET, POST, OPTIONS  

Access-Control-Allow-Headers: Authorization, Content-Type  

→ Это называется Preflight-запрос, который используется для проверки разрешённых методов при работе с CORS (межсайтовыми запросами).

Метод OPTIONS помогает клиенту узнать, какие методы поддерживаются в API, и избежать ошибок при отправке неподдерживаемых запросов.

 

Основные свойства метода OPTIONS

OPTIONS является идемпотентным

  • Повторные OPTIONS-запросы не изменяют состояние сервера.

  • Они только возвращают информацию о поддерживаемых методах.

Влияние на безопасность и состояние сервера

  • OPTIONS не изменяет состояние сервера, а лишь запрашивает данные для их чтения, что делает его безопасным методом.

  • Безопасен с точки зрения передачи данных, так как они не передаются, а только запрашиваются.

  • Однако сервер может ограничить его использование по соображениям безопасности.

Передача данных

  • OPTIONS не требует тела запроса, но может передавать заголовки для уточнения параметров.

  • Ответ содержит заголовки с перечнем поддерживаемых методов и иногда CORS-настройки.

Ограничения длины URL отсутствуют

  • Как и GET/HEAD, OPTIONS передаёт параметры через URL.

  • Ограничения зависят только от браузеров и серверов.

Форматы данных

  • OPTIONS не возвращает тело ответа, только заголовки (Allow, Access-Control-Allow-Methods).

  • Может возвращать 204 No Content, если сервер не передаёт дополнительных данных.

Кэширование

  • OPTIONS не кэшируется браузерами, так как его результат зависит от настроек сервера.

  • Однако CORS-запросы могут кешироваться через заголовок Access-Control-Max-Age.

 

Дополнительные особенности метода OPTIONS

OPTIONS используется для CORS

  • При кросс-доменных запросах браузер отправляет preflight-запрос, чтобы проверить, можно ли выполнять операцию.

OPTIONS помогает избежать ошибок API

  • Перед отправкой запроса клиент может уточнить, какие методы поддерживаются, чтобы не отправлять неподдерживаемые.

OPTIONS может использоваться как на уровне всего API, так и для конкретного ресурса.

  • OPTIONS — запрашивает информацию обо всех методах API.

  • OPTIONS /users — запрашивает информацию о методах для конкретного ресурса.

Метод OPTIONS полезен для предварительной проверки API, работы с CORS и диагностики поддерживаемых методов.

 

Итог

Метод OPTIONS используется для запроса информации о поддерживаемых HTTP-методах и часто применяется для работы с CORS. Он не изменяет состояние сервера, а только возвращает разрешённые методы и заголовки.

 

Как тестируют OPTIONS?

  • Проверяют, возвращает ли сервер корректный список методов (Allow: GET, POST, PUT, DELETE).

  • Тестируют CORS-настройки (Access-Control-Allow-Methods, Access-Control-Allow-Headers).

  • Проверяют, не возвращает ли сервер тело ответа, если этого не требуется (204 No Content).

  • Убеждаются, что OPTIONS не меняет данные на сервере.

Метод OPTIONS помогает клиенту узнать возможности API и избежать ошибок, отправляя неподдерживаемые запросы.
