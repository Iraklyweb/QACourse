Лекция «WADL: аналог WSDL для REST»

 

WADL (Web Application Description Language) — это стандарт для описания REST API, написанный на XML. Он выполняет ту же роль, что и WSDL в SOAP, но используется в контексте REST. WADL описывает ресурсы, методы, параметры и формат данных, что помогает разработчикам и тестировщикам понять, как правильно взаимодействовать с API. Не является обязательным элементом в REST.

 

Что описывает WADL?

  1. Ресурсы. Это основные элементы REST API (например, users, orders, products), куда ходит клиент.

  2. Методы. WADL указывает, какие HTTP-методы можно использовать с ресурсами (например, GET, POST, PUT, DELETE и др.).

  3. Параметры. Описывает, какие параметры можно передавать в запросе, их типы и обязательность.

  4. Ответы. Указывает, какие данные возвращает API и в каком формате (например, JSON, XML).

 

Пример WADL

Пример WADL для API, которое возвращает список пользователей:

<application xmlns="http://wadl.dev.java.net/2009/02">

    <resources base="https://example.com/api">

        <resource path="/users">

            <method name="GET">

                <response>

                    <representation mediaType="application/json"/>

                </response>

            </method>

        </resource>

    </resources>

</application>

 

Расшифровка:

  • <resources> описывает базовый URL для всех запросов.

  • <resource path="/users"> указывает, что доступен ресурс /users.

  • <method name="GET"> показывает, что к этому ресурсу можно обратиться методом GET.

  • <representation mediaType="application/json"/> говорит, что ответ будет в формате JSON.

 

Почему WADL используется редко?

  1. REST гибкий и лёгкий. WADL часто считают слишком громоздким для REST, который задумывался как лёгкий и нестрогий.

  2. OpenAPI (Swagger) вытеснил WADL. Индустрия перешла на OpenAPI, который проще в использовании и имеет больше инструментов для работы.

 

Итог

WADL — это попытка стандартизировать описание REST API с помощью формата XML, аналогично тому, как WSDL используется для SOAP. Он описывает ресурсы, методы, параметры и форматы данных. Однако на практике WADL используется крайне редко. Современным и более популярным стандартом описания REST API стал OpenAPI (Swagger) — благодаря простоте, читабельности и мощным инструментам для генерации документации и тестирования.

 

 

Что нужно уметь рассказать
– Термин «WADL»
– WADL = описание REST API в XML
– Аналог WSDL, но для REST
– Что описывает: ресурсы, методы, параметры, ответы, форматы данных
– На практике почти не используется
– Современная альтернатива — OpenAPI (Swagger)
