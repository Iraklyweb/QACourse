Лекция «ID»

Тестовая документация · Паспорт и классификация документа

ID

ID — уникальный идентификатор, по которому элемент можно найти или сослаться на него. Применяется во всех типах тестовой документации для связи между объектами.

Он нужен, чтобы любой элемент тестовой документации можно было быстро найти и связать с другими артефактами.

Внутри компании он играет ту же роль, что номер паспорта у человека: помогает отличить один объект от другого, даже если названия похожи.

В разных инструментах ID создаётся по-разному.

В TestIT или Zephyr он может формироваться автоматически — например, TC-125 для тест-кейса или BUG-432 для дефекта.

Если вы работаете в таблице, ID можно проставлять вручную: обычный числовой или буквенно-числовой индекс, главное — чтобы он был уникальным и не пересекался с другими.

Когда таких документов становится сотни, ID перестаёт быть “просто колонкой”.

Он помогает:

— делать ссылки между тестами, багами и задачами;

— понимать, к какому элементу относится комментарий или лог;

— не потерять документ при миграции или выгрузке.

Если документация ведётся в Excel, часто ошибаются с нумерацией: дублируют ID, пропускают значения, вставляют новые строки без обновления.

Из-за этого теряется связь между тестами и дефектами — система перестаёт быть целостной.

Поэтому даже в простой таблице лучше заранее определить формат ID и придерживаться его.

Например:

TC-001 — тест-кейс,

CL-015 — пункт чек-листа,

BR-207 — баг-репорт.

Такой порядок помогает сохранять структуру и не терять связи, даже если документация ведётся вручную.

Система не должна быть сложной — главное, чтобы её понимали все, кто с ней работает.
