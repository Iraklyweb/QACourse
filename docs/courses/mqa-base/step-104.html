Тестирование по таблицам причин и следствий — практическое применение

Метод таблиц причин и следствий используется, когда система реагирует на несколько условий, и каждое из них может по-разному влиять на результат.

На практике это помогает выявить, какие комбинации причин действительно приводят к определённым последствиям, а какие — не влияют на поведение системы.

Где применяется

Техника актуальна там, где логика построена на множестве зависимостей и вложенных условий.

Например:

  • — расчёт итоговой комиссии по набору признаков (тип клиента, валюта, регион);
  • — применение бизнес-правил, зависящих от нескольких параметров;
  • — выбор приоритета при конфликте условий (например, при наложении двух скидок или правил доступа);
  • — автоматические решения — одобрить, отклонить, запросить уточнение.

Если таблица принятия решений показывает все комбинации условий, то таблица причин и следствий помогает понять, почему именно такая комбинация приводит к конкретному результату.

Как выглядит процесс

Тестировщик получает набор условий и результатов из требований или логики кода.

Он:

  • — выделяет все возможные причины — входные данные, состояния или флаги, влияющие на логику;
  • — определяет все следствия — действия или результаты, которые могут произойти;
  • — строит граф зависимостей: какие причины влияют на какие следствия;
  • — по графу формирует таблицу и тесты для каждой комбинации связей.

Как читать результат

Система одобрения заявки на кредит.

Причины:

  • C1 — доход выше 100 000 рублей,
  • C2 — нет текущих долгов,
  • C3 — положительная кредитная история.

Следствия:

  • E1 — заявка одобрена,
  • E2 — требуется ручная проверка,
  • E3 — заявка отклонена.

Связи:

— если C1, C2 и C3 истинны → E1 (одобрена);

— если C1 и C2 истинны, но C3 ложна → E2 (ручная проверка);

— если C2 ложна → E3 (отклонена).

Причины / Следствия C1 C2 C3 E1 E2 E3
Тест 1 1 1 1 1 0 0
Тест 2 1 1 0 0 1 0
Тест 3 1 0 1 0 0 1

(1 — условие выполняется, 0 — не выполняется.)

Из таблицы тестировщик создаёт три теста, каждый из которых проверяет связь “причина → следствие”.

Если при тестировании наблюдается поведение, не описанное в таблице, — значит, в логике или в требованиях есть пропуск.

На что обращать внимание

  • — Применять, когда таблицы принятия решений становятся слишком громоздкими.
  • — Использовать для визуализации логики перед автоматизацией — упрощает написание unit-тестов.
  • — Хорошо подходит для API и расчётных сервисов, где одно поле может влиять на другое.

Итог

Тестирование по таблицам причин и следствий помогает связать входные данные с результатом и увидеть реальную структуру логики.

Это не просто способ формировать тесты, а инструмент анализа: он показывает, какие комбинации условий действительно влияют на систему, а какие лишние.

Так тестировщик получает не набор случайных проверок, а полную карту взаимосвязей поведения системы.
